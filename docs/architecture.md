# AegisFlow System Architecture

## Overview
AegisFlow is an enterprise payment fraud scoring and agentic anti-money-laundering (AML) investigation platform. It unites real-time ML feature ingestion and scoring with autonomous multi-agent SAR investigation workflows.

```
Transaction Generator
        │
        ├───────────────────────┐
        ▼                       ▼
 Ingestion API ────────► Redis (Online Features)
        │
        ▼
 PostgreSQL (RDBMS + Entity Graph Storage)
        │
        ▼
  Scoring Service
  ├─ Rules Engine (Deterministic Override)
  ├─ XGBoost Champion Model
  ├─ LightGBM Challenger (Shadow Mode)
  ├─ SHAP TreeExplainer
  └─ Isotonic Probability Calibration
        │
        ▼
  Decision: APPROVE / REVIEW / DECLINE
        │
        ▼
  Alert Engine ──► Case Management Queue
                       │
                       ▼
         Investigation Orchestrator (LangGraph)
         ├── Supervisor Agent
         ├── Link Analyst Agent
         ├── Pattern Analyst Agent
         ├── Adverse Media Researcher (Qdrant RAG)
         ├── Narrative Writer Agent
         └── QA Reviewer Agent
                       │
                       ▼
              Evidence Pack & SAR Draft
                       │
                       ▼
             Human Analyst Review (Mandatory)
```

## Key Architectural Principles
1. **Single Source of Truth Feature Store**: `ml/features/definitions.py` governs both offline batch training feature engineering and Redis online streaming feature updates.
2. **Ground-Truth Label Isolation**: Ground-truth labels generated by synthetic data streams reside strictly in `ground_truth_labels` and are never accessible to online scoring APIs.
3. **Deterministic Tools, LLM Interpretation**: LangGraph agents consume structured outputs from calculation tools (`khop_neighborhood`, `velocity_summary`, `adverse_media_search`).
4. **Mandatory Human Approval**: SAR filings cannot occur autonomously. Human approval with reviewer identity and rationale is mandatory.
